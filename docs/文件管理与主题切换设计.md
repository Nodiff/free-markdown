# 文件管理与主题切换 · 交互设计稿

> 状态：待评审，尚未改代码。日期：2026-11-24。
> 范围：主题三态切换；左栏文件树的「新建文档 / 新建文件夹 / 重命名 / 删除」。
> 不在本轮：拖拽移动、多选批量操作、复制粘贴、跨库移动、全文索引。

---

## 一、总体结论

1. **文件管理不另做“管理中心”**，全部围绕左栏真实目录树完成：树内就地新建、就地重命名、右键/更多菜单删除。库目录仍是唯一真相。
2. **新建与重命名都用行内输入框**，不弹大表单。Enter 确认、Esc 取消；重命名失焦即提交，校验失败则留在输入态并给具体原因。
3. **删除复用应用回收站**：单文件“移到回收站 + 8 秒撤销 toast”，文件夹走二次确认。任何删除都可从回收站还原；文件夹整目录进出。
4. **主题是设置里的三态选择**（跟随系统 / 浅色 / 深色），默认跟随系统；切换即时生效，不写库目录，只写 `userData/config.json`。深色必须覆盖编辑器、预览、mermaid、弹窗、diff、toast，绝不做整体反色滤镜。
5. 所有操作仍走命令注册表 + 主进程 IPC；渲染层不碰 `fs`，路径一律经 `resolveInside` 校验。

## 二、文件管理交互

### 2.1 入口布局

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 新建 | 左栏库名右侧一个 `＋` 胶囊 | 点开锚定小菜单：「新建文档 ⌘N」「新建文件夹 ⌘⇧N」；不在树里常驻一排按钮 |
| 行内更多 | 树行 hover / 选中时右侧 `⋯` | 打开同一套上下文菜单；比纯右键更好发现 |
| 右键 | 树行 / 树空白处 | 树行先选中再弹菜单；空白处只给新建类操作 |
| 快捷键 | `⌘N` / `⌘⇧N` | 在当前目标目录新建文档 / 文件夹 |
| 重命名 | 上下文菜单、`F2` | 树行就地变成输入框 |
| 删除 | 上下文菜单、`⌘⌫` | 当前打开文档或选中项移入回收站 |

**“当前目标目录”判定**（新建筑一）：
1. 树里显式选中的文件夹 → 该文件夹；
2. 否则当前打开文档所在目录；
3. 否则库根。

**选中态**：新增独立于“打开文档”的 `selectedPath`。点文件夹 = 选中并展开/收起；点文档 = 选中并打开。选中行用浅底色；打开文档行左侧仍有强调线，二者可同时成立。右键任何行先把它设为选中，避免“菜单操作了另一个文件”。

### 2.2 新建

**新建文档**
- 在目标目录的第一行插入一条“草稿行”：`[md 图标] [输入框：未命名] .md`，输入框自动聚焦并全选。
- 只编辑主文件名，`.md` 作为灰色固定后缀显示，避免用户误删扩展名。
- Enter：创建并立即打开；文件内容为空（UTF-8、LF、无 BOM），标题由首个 H1 / 文件名规则接管。
- Esc：草稿行消失，不产生空文件。
- 失焦：等同 Enter；若名字为空则回退到默认名，不阻断。
- 默认名按语言：`未命名.md` / `Untitled.md`；同级重名自动 `未命名 2.md`、`未命名 3.md`。
- 目标目录若未展开：先展开、滚到可见，再出现草稿行。
- 创建成功 toast：`已创建 未命名.md`，可点「打开」；实际已自动打开，toast 只用于确认。

**新建文件夹**
- 同样草稿行，图标为文件夹，无固定后缀；Enter 创建后自动展开该空文件夹并选中。
- 空文件夹显示现有空态文案，但补一行轻提示「右键或 ＋ 在这里新建文档」。

**校验与错误**（输入框下方一行红字，不关闭输入态）：
- 空名 / 全是空格 →「名字不能为空」；
- 含 `/`、`\`、空字节 →「名字里不能包含斜杠」；
- `.`、`..`、`.git`、`node_modules`、`.DS_Store` →「这是保留名称」；
- 同级已存在（macOS 大小写不敏感）→「同级已有同名文件」；
- 无写权限 →「没有写入权限」。
- 后端再做一次同名与越界校验；前端校验只负责即时反馈，不作为安全边界。

### 2.3 重命名

**交互**
- 树行在原位变成输入框，不回弹窗。文件名默认只选中主文件名，扩展名保持灰色后缀；文件夹整名选中。
- Enter / 失焦提交；Esc 还原；提交中行呈半透明忙碌态，防重复。
- 只允许改当前层级名字，不允许输入 `/` 换目录；“移动到别的目录”不在本轮。
- 名字未变 → 直接退出，不发 IPC、不产生历史噪声。
- 大小写改名（`Foo.md` → `foo.md`）允许；macOS 大小写不敏感文件系统上用临时名两步 rename，避免“看起来成功但其实没变”。

**与当前文档联动**
1. 若被重命名的是当前打开文档且 `dirty`：先 `save()`；保存失败则中止重命名并 toast「保存失败，未重命名」。
2. 成功后同步：`docStore.relPath`、`vaultStore.activePath`、header 标题、最近使用、`metaStore` 索引。
3. 重命名文件夹：把 `expanded` 中以旧前缀开头的路径整体替换为新前缀并持久化；若当前文档在该目录内，同样改路径；若回收站首页视图正打开，刷新元数据。
4. 树只重载父目录，不整树重建，保留滚动位置。

**冲突**
- 目标已存在 → 留在输入态，红字「同级已有同名项」，全选名字；
- 源已不存在（外部刚删）→ 关闭输入态，toast「文件已不存在」，刷新树。

### 2.4 删除

**单文件 / 单文档**
- 不弹阻塞确认。执行「移到回收站」后 toast：
  `已移到回收站：notes/food.md`　[撤销]
- 撤销窗口 8 秒；点「撤销」调用现有 `trash.restore`，若原名被占用则自动 ` (1)`，toast 说明改名结果。
- 删除前若文件是当前文档且 `dirty`，先 flush 保存，保证回收站里是最新内容；保存失败则中止删除。
- `⌘⌫` 与右键「移到回收站」走同一条命令，不再直接静默删除。

**文件夹**
- 二次确认卡（复用现有直角确认卡样式）：
  - 标题：`删除文件夹 “projects”？`
  - 正文：`文件夹及其中的全部内容会移入应用回收站，可整目录还原；库内文件不会被直接抹掉。`
  - 按钮：`取消` / `移到回收站`（危险色）
- 确认后整目录 rename 进回收站，保留相对结构，`TrashEntry.isDir = true`。
- 若当前打开文档位于该目录内：关闭编辑器、清空 active、显示空态；toast 说明「当前文档已随文件夹移入回收站」。

**删除后的状态**
- 树：刷新父目录；若删的是展开目录，清掉该目录及子路径的 `children` / `expanded`。
- 当前文档：被删则清空；未被删则不动。
- 回收站：立即可见，文件夹行显示文件夹图标 + 「文件夹」；还原按钮还原整目录。
- 历史：删除表现为工作区 `D`，进「文档变更」，不打自动快照。切回旧快照可恢复，沿用 M5 语义。

### 2.5 状态同步清单（实现时逐项打勾）

| 状态 | 新建 | 重命名 | 删除 |
| --- | --- | --- | --- |
| 文件树父目录 | 重载 + 滚动到新行 | 只重载父目录 | 重载父目录 |
| 展开状态 | 目标目录展开 | 目录前缀整体替换 | 删除目录及其子路径 |
| 当前文档 | 打开新文档 | 改 relPath / 标题 | 清空或保持 |
| 分类与最近使用 | rescanIndex | rescanIndex + 最近记录改路径 | rescanIndex |
| 文档变更 | 出现 `A` | 出现 `D + A` | 出现 `D` |
| 回收站计数 | 不变 | 不变 | +1，UI 立即更新 |
| 搜索面板 | 若开着，提示「库已变化，重新搜索」 | 同左 | 同左 |
| 空态 | 新目录空时提示可新建 | 无 | 目录空/库空回到引导态 |

### 2.6 上下文菜单结构

树行（Markdown）：
```
新建文档…            ⌘N
新建文件夹…          ⌘⇧N
────────────
重命名…              F2
移到回收站…          ⌘⌫
────────────
设置分类…             （保留现有分类弹层）
在 Finder 中显示
复制相对路径
```
树行（文件夹）：新建两项、重命名、移到回收站、在 Finder 中显示、复制相对路径。
树行（其他文件）：重命名、移到回收站、在 Finder 中显示、复制相对路径；不提供分类与“新建到此”。
空白处：新建文档、新建文件夹、在 Finder 中显示库根。

菜单宽 220px、直角 2px、阴影轻、危险项红字；点击外部 / Esc 关闭；贴近窗口边缘时自动翻转。菜单一次只开一个，和分类弹层互斥。

## 三、主题切换

### 3.1 设置交互

设置面板新增「外观」区，放在「语言」上方：

```
外观
[ 跟随系统 ] [ 浅色 ] [ 深色 ]
当前：跟随系统（深色）
```

- 三选一，选中即生效并持久化，无「保存」按钮。
- 每项带小图标（显示器 / 太阳 / 月亮）；选中项用 accent 边框 + 浅底，不用大面积色块。
- 选「跟随系统」时，副文案实时显示系统当前解析结果（浅色/深色）；系统切换时应用无需重启。
- 命令面板增加 `theme.system` / `theme.light` / `theme.dark` 三条命令；不加列头图标，避免列头已有四个胶囊再膨胀。
- 首次启动默认「跟随系统」，迁移旧配置时也按此默认，不改变现有用户观感。

### 3.2 深色视觉基线

| Token | 浅色 | 深色 |
| --- | --- | --- |
| `--bg` | `#ffffff` | `#15171b` |
| `--panel` | `#ffffff` | `#1b1e23` |
| `--panel-alt` | `#fbfbfc` | `#181b20` |
| `--border` | `#e6e8ec` | `#2a2e35` |
| `--text` | `#1f2329` | `#e6e8ec` |
| `--text-dim` | `#5c6470` | `#a7aeb9` |
| `--muted` | `#98a0ab` | `#7d8692` |
| `--accent` | `#2f6fed` | `#6f9dff` |
| `--accent-soft` | `#eaf0fe` | `#202b44` |
| 新增行底 | `#e8f7ec` | `#17301f` |
| 删除行底 | `#fdecec` | `#351b1e` |

原则：
- 背景不用纯黑，正文对比度 ≥ 7:1；禁用态和占位符 ≥ 4.5:1。
- 边框用低对比度分层，不用阴影堆叠；保持现有“全直角、无栏缝”。
- 图片、视频、用户内容不做反色/降亮滤镜。
- 滚动条、文本选区、focus ring、toast、弹窗遮罩都纳入深色 token，不留白块。
- 预览代码块、表格斑马纹、引用块、KaTeX 公式色、mermaid 节点与连线全部单独定义，不依赖浏览器默认。

### 3.3 技术落地

1. **配置**：`AppConfig.ui.theme: 'system' | 'light' | 'dark'`，默认 `system`；`normalize` 对旧配置补默认，版本仍为 1。
2. **原生外观**：主进程启动时按配置设置 `nativeTheme.themeSource = preference`，再创建窗口；这样 mac 红绿灯、原生菜单、原生对话框与 `prefers-color-scheme` 同向，且启动不闪白。设置变化时经新增 `app:setThemeSource` IPC 立即更新。
3. **CSS**：保留 `:root` 浅色 token，新增 `@media (prefers-color-scheme: dark)` 覆盖；同时给 `html` 写 `color-scheme`。不靠 React 根节点 class，避免首帧闪。
4. **CodeMirror**：新增深色 theme + highlight style，放进 `Compartment`；主题变化只 `dispatch` 重配置，不重建 EditorView，undo 历史与滚动位置不动。
5. **mermaid**：缓存 key 加主题；主题切换时清空渲染缓存并 bump 预览刷新令牌，重新串行渲染。初始化配置同步换 `themeVariables`；避免浅色 SVG 留在深色画布上。
6. **预览**：所有写死颜色收敛到 token；代码高亮、表格、blockquote、KaTeX、脚注区逐块核对。
7. **导出**：M7 的 PDF / Word 永远用浅色打印样式，不受应用深色影响；HTML 导出带用户当前主题变量但默认浅色，避免打印出黑底。

### 3.4 主题验收

- 三态切换即时生效；重启后保持；系统主题变化时「跟随系统」自动跟随。
- 浅→深→浅往返后，编辑器撤销历史、滚动位置、预览滚动位置不丢。
- 含 mermaid 四类图、KaTeX、表格、代码块、脚注的文档，深色下无白底残留、无低对比文字。
- 快照抽屉、diff 红绿底、保存弹窗、冲突弹窗、搜索三栏、回收站、toast 全部可读。
- 启动首帧不闪白；mac 红绿灯与窗口底色一致。
- 100 次切换无内存增长异常（mermaid 缓存有上限）。

## 四、后端与 IPC 设计

新增 `files` 命名空间，仍是纯增量，`API_VERSION` 不升：

| 通道 | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| `files:create` | `{ dir, name, kind: 'md' \| 'dir' }` | `{ relPath, node }` | 校验 + 唯一名 + 写空文件/建目录 |
| `files:rename` | `{ relPath, name }` | `{ relPath, oldRelPath }` | 仅同级改名；目录返回新前缀 |
| `files:remove` | `{ relPath }` | `TrashEntry` | 复用 `moveToTrash`，支持目录 |
| `files:reveal` | `{ relPath }` | `void` | `shell.showItemInFolder` |
| `files:copyPath` | `{ relPath }` | `string` | 相对路径，渲染层写剪贴板（或主进程写） |

预期错误不抛裸异常，统一返回：
```ts
type FileOpErrorCode = 'exists' | 'invalid-name' | 'not-found' | 'permission' | 'unsupported'
type FileOpResult<T> = { ok: true; value: T } | { ok: false; code: FileOpErrorCode; message: string }
```
意外错误仍抛，渲染层统一 toast，不静默吞。

主进程新增 `services/fileOps.ts`：
- 名字校验：trim、长度 ≤ 120、禁 `/ \ NUL`、禁 `.`/`..`、禁保留名；
- 同名检测用 `readdir` 后按 `localeCompare(..., sensitivity:'base')`，覆盖 macOS 大小写不敏感；
- 新建先 `open(..., 'wx')` 原子占位，避免并发覆盖；空文档写 UTF-8 空串；
- 重命名先 `stat` 源、再检查目标；目录改名前确认目标不存在；
- 删除前 `flush` 当前文档由渲染层负责，主进程只处理路径。

事件：
- 操作成功后立即广播 `tree:changed` 父目录（不等 watcher 的 500ms），同时调用 `metaIndex.rescanIndex()` 与回收站广播；
- watcher 随后到达的同类事件做幂等刷新，不重复 toast；
- 历史 `noteWorkingTreeChanged` 自然刷新「文档变更」，不主动打快照。

## 五、命令与快捷键

| 命令 | 快捷键 | 行为 |
| --- | --- | --- |
| `file.new` | `⌘N` | 在当前目标目录新建文档 |

## 七、已确认的交互决策（2026-11-24）

1. **新建入口**：左栏库名右侧常驻 `＋`，点开「新建文档 / 新建文件夹」小菜单；树行与空白处同时支持右键。
2. **重命名**：树内就地输入，像 Finder；Enter 提交、Esc 还原，只选中主名并保留 `.md` 后缀。
3. **单文件删除**：立即移入回收站，toast 提供 8 秒「撤销」；超时后仍可从回收站还原。
4. **文件夹删除**：固定二次确认，明确「整目录移入回收站、可还原」。
5. **主题**：设置页三态，默认跟随系统；切换即时生效并持久化到 `userData/config.json`。

以上为后续实现的基线；若实现中出现与现有架构冲突，先回到本稿改设计，不直接改交互口径。

## 八、验收脚本（打包后按此逐条走）

1. 库根 `⌘N` → 行内输入 `周会` → Enter：生成 `周会.md`、自动打开、左栏出现、文档变更为 `A`。
2. 新建时输入已存在名字：红字提示，输入态不关闭；改名后 Enter 成功。
3. 选中 `notes` → `⌘⇧N` → 建 `草稿` 文件夹：自动展开并显示空态提示。
4. 重命名当前打开且有未保存内容的文档：先保存再改名，标题即时更新，撤销历史仍在。
